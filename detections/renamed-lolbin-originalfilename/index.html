renamed LOLBIN caught by an OriginalFileName mismatch

ATT&CK · T1036.003 (Rename System Utilities) Tactic · Defense Evasion
Hypothesis. A process whose embedded PE OriginalFileName is a well-known living-off-the-land binary while its on-disk name is something else is the classic rename used to slip a LOLBIN past name-based rules. The OriginalFileName lives in the version resource and does not change when the file is renamed, so the mismatch is a strong masquerade signal.

context

The version resource is the anchor. Rename powershell.exe to svchost-helper.exe and the file still carries PowerShell.EXE as its OriginalFileName, because that field travels inside the binary. Name-based rules key on the on-disk name and miss the swap. This rule keys on the field that does not move.

It covers the usual interpreters and dual-use tools, PowerShell, cmd, reg, regsvr32, rundll32, mshta, the script hosts, certutil, bitsadmin, wmic, schtasks, and net. A match means the real tool is present under a cover name.

hunt

Match a LOLBIN OriginalFileName that disagrees with the on-disk image name.

// hypothesis: a LOLBIN OriginalFileName not matching the on-disk name.

FROM logs-edr-process_events
| WHERE TO_LOWER(process.pe.original_file_name) IN ("powershell.exe", "cmd.exe", "reg.exe", "rundll32.exe", "mshta.exe", "certutil.exe", "wmic.exe")
| WHERE TO_LOWER(process.name) != TO_LOWER(process.pe.original_file_name)
| KEEP host.name, process.name, process.pe.original_file_name, process.command_line
| SORT @timestamp DESC
| LIMIT 100

findings & discriminators

  • The field that does not move. A renamed file keeps its original name in the version resource, so a mismatch is the rename itself.
  • Read the command line. A renamed interpreter running scripted commands is the finding, not a deployment tool that copied a binary under a product name.
