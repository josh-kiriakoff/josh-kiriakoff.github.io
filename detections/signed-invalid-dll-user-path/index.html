signed-but-invalid DLL loaded from a user path

ATT&CK · T1574.002 (DLL Side-Loading) ATT&CK · T1036.001 (Invalid Code Signature) Tactic · Defense Evasion
Hypothesis. A DLL that carries an Authenticode signature whose status does not validate, expired, revoked, or a broken chain, loading from a user-writable path is the fingerprint of a tampered or re-signed module. An operator patched a signed DLL, or stapled a stale certificate to a payload to satisfy allow-listing that only checks a signature is present rather than valid.

context

The gap this rule targets is a specific weak control. Some allow-lists ask only whether a signature exists, not whether it verifies. A present-but-invalid signature is exactly what you get when someone edits a signed binary after the fact, because the edit breaks the hash the signature covers.

Pairing the invalid status with a user-writable source path keeps it honest. A legitimately expired vendor certificate on old software can produce a non-valid status too, so the load location does the separating.

hunt

Match a signed DLL whose signature is not valid loading from a user path.

// hypothesis: signed-but-invalid DLL loading from a user path.

FROM logs-edr-library_events
| WHERE dll.code_signature.signed == true
| WHERE dll.code_signature.status != "valid"
| WHERE TO_LOWER(dll.path) LIKE "*\\users\\*"
     OR TO_LOWER(dll.path) LIKE "*\\appdata\\*"
     OR TO_LOWER(dll.path) LIKE "*\\temp\\*"
| KEEP host.name, process.executable, dll.path, dll.code_signature.status
| SORT @timestamp DESC
| LIMIT 100

findings & discriminators

  • Present but invalid is the point. A broken or revoked signature on a module means the file changed after signing, or the certificate was borrowed.
  • Location keeps it clean. Old vendor software with an expired certificate is the main benign case, so the user-writable path is what separates it from tampering.

Rule. Detects a DLL that carries an Authenticode signature whose status is NOT valid (expired, revoked, or a broken chain) being loaded from a user-writable directory. Rated medium.

logsource:
  category: image_load

detection:
  selection_signed:
    Signed: 'true'
  selection_path:
    ImageLoaded|contains:
      - '\Users\'
      - '\AppData\'
      - '\Temp\'
      - '\ProgramData\'
      - '\Public\'
      - '\Downloads\'
  filter_valid:
    SignatureStatus: 'Valid'
  condition: selection_signed and selection_path and not filter_valid
fields:
  - Image
  - ImageLoaded
  - SignatureStatus

  - Legitimately expired vendor certificates on older software occasionally produce a non-valid status. Confirm the signer and whether the DLL was modified after signing.
