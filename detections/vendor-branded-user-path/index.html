vendor-branded executable running from a user path

ATT&CK · T1036.005 (Match Legitimate Name) ATT&CK · T1036.001 (Invalid Code Signature) Tactic · Defense Evasion
Hypothesis. A process whose PE metadata claims a major vendor, Microsoft, Google, or Mozilla, while the binary runs from a user-writable path outside that vendor's real install and update locations is a masquerade. Copying a vendor's version resources onto a payload is a cheap way to survive a glance and some allow-lists.

context

The mismatch is the signal. A binary that says it is Microsoft has no business running from a user temp folder, because Microsoft ships to Program Files, the component store, and a known set of updater paths. The claimed publisher and the execution path disagree, and that disagreement is hard to fake away.

The rule allow-lists the real vendor directories, the Edge and Chrome updaters, OneDrive, Teams, the package cache, and the like, so what remains is a vendor name running from somewhere the vendor never installs.

hunt

Match a vendor-branded process running from a user path outside the vendor's real directories.

// hypothesis: vendor-branded PE running from a user-writable path.

FROM logs-edr-process_events
| WHERE process.pe.company IN ("Microsoft Corporation", "Google LLC", "Mozilla Corporation")
| WHERE TO_LOWER(process.executable) LIKE "*\\appdata\\*"
     OR TO_LOWER(process.executable) LIKE "*\\temp\\*"
     OR TO_LOWER(process.executable) LIKE "*\\downloads\\*"
| WHERE NOT TO_LOWER(process.executable) LIKE "*\\microsoft onedrive\\*"
     AND NOT TO_LOWER(process.executable) LIKE "*\\google\\update\\*"
| KEEP host.name, process.executable, process.pe.company, process.command_line
| SORT @timestamp DESC
| LIMIT 100

findings & discriminators

  • The publisher and the path disagree. A Microsoft-branded binary in a user temp folder is claiming a trust its location contradicts.
  • Extend the allow-list to the environment. Some updaters stage vendor-signed binaries in temp or ProgramData, so add the known ones as they surface.

detection:
  selection_vendor:
    Company:
      - 'Microsoft Corporation'
      - 'Google LLC'
      - 'Mozilla Corporation'
  selection_userpath:
    Image|contains:
      - '\AppData\'
      - '\Users\Public\'
      - '\Windows\Temp\'
      - '\Downloads\'
      - '\ProgramData\'
      - '\Temp\'
  filter_legit_vendor_dirs:
    Image|contains:
      - '\Microsoft\EdgeUpdate\'
      - '\Microsoft\EdgeWebView\'
      - '\Microsoft OneDrive\'
      - '\Microsoft\Teams\'
      - '\Microsoft\WindowsApps\'
      - '\WindowsApps\'
      - '\Package Cache\'
      - '\Google\Update\'
      - '\Google\Chrome\'
      - '\Mozilla\'
      - '\Mozilla Firefox\'
  condition: selection_vendor and selection_userpath and not filter_legit_vendor_dirs
fields:
  - Image
  - Company
  - CommandLine
  - ParentImage
falsepositives:
  - Some legitimate installers and auto-updaters stage vendor-signed binaries in temp or ProgramData. Extend the allow-list with the environment's known updater paths as they surface.
