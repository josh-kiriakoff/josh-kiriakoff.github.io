legacy netsh firewall context enabling remote access

ATT&CK · T1562.004 (Disable or Modify Firewall) ATT&CK · T1021.001 (RDP) Tactic · Defense Evasion Tactic · Lateral Movement
Hypothesis. Microsoft deprecated the netsh firewall context in Windows Vista in favour of netsh advfirewall. Its appearance in a modern intrusion, enabling the remoteadmin or remotedesktop exception, is a copy-forward hardening script rather than current administrative practice.

context

The deprecated syntax is the signal. An operator reusing a years-old playbook keeps whatever worked the first time, and the old set service form still works. A current administrator reaches for advfirewall. The gap between the two is what this rule reads.

It is scoped tightly on purpose. It fires on the legacy service-enable form opening remote administration or remote desktop, and it does not overlap rules for advfirewall or for turning the firewall off outright. I watched netsh flip a firewall exception during the domain controller case linked below.

hunt

Match the deprecated netsh firewall set service form enabling a remote exception.

// hypothesis: deprecated netsh firewall context enabling remote access.

FROM logs-edr-process_events
| WHERE TO_LOWER(process.name) == "netsh.exe"
| WHERE TO_LOWER(process.command_line) LIKE "*firewall*"
     AND TO_LOWER(process.command_line) LIKE "*set service*"
| WHERE TO_LOWER(process.command_line) LIKE "*remoteadmin*"
     OR TO_LOWER(process.command_line) LIKE "*remotedesktop*"
| KEEP host.name, process.parent.name, process.command_line
| SORT @timestamp DESC
| LIMIT 100

findings & discriminators

  • The legacy context is the tell. Modern management uses advfirewall. The Vista-era form surviving into a 2026 intrusion is the operator carrying an old script forward.
  • Verify the host and operator. A genuinely ancient deployment image can still carry this syntax, so confirm who ran it and what else happened in the session.
